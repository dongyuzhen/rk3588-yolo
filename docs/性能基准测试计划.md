# RK3588 流水线性能基准测试计划

## 一、流水线全貌与测量点

```
Camera (V4L2)
  │  [A] 采集延迟
  ▼
captureThreadFunc        ─── 入 readQueue
  │
  ▼
processThreadFunc
  │  [B] 出队等待时间
  ▼
┌─────────────────────────────────────────────────────┐
│ Yolov5s::inference_image(dmabuf_fd)                │
│   [C] RGA: NV12→RGB888 letterbox (1920×1080→640×640) │
│   [D] RKNN NPU 推理 (INT8, 640×640)                │
│   [E] 后处理 decode + NMS                          │
└─────────────────────────────────────────────────────┘
  │
  ▼
writeThreadFunc
  │  [F] IoU Tracker 匹配                            │
  │  [G] CPU OSD 画框 (BGRA mat)                     │
  │  [H] RGA: NV12 copy + BGRA blend → MPP buffer    │
  │  [I] MPP H.264 硬件编码                          │
  │  [J] RTSP 推流                                   │
  │  [K] 报警引擎 (仅在违规时触发)                    │
  ▼
```

## 二、测量精度要求

| 测量项 | 精度 | 方法 |
|--------|------|------|
| 端到端帧延迟 | ±1ms | `steady_clock` 打点 |
| NPU 推理耗时 | ±100μs | 排除首次 warmup，取 P50/P99 |
| RGA 操作耗时 | ±10μs | RGA 硬件是同步调用 (IM_SYNC) |
| 队列等待时间 | ±1ms | 入队前/出队后时间戳差 |
| 内存/带宽 | MB | `/proc/meminfo`、ion 统计 |

## 三、实现方案：代码插桩

### 3.1 核心计时器工具类

新建文件 `bench/perf_timer.h`：

```cpp
#pragma once
#include <chrono>
#include <string>
#include <vector>
#include <map>
#include <algorithm>
#include <numeric>
#include <fstream>
#include <iostream>
#include <mutex>

using namespace std::chrono;

struct PerfRecord {
    std::string name;
    double      total_ms;       // 累计耗时
    int         count;          // 采样次数
    double      min_ms;         // 最小
    double      max_ms;         // 最大
    std::vector<double> samples; // 原始数据（可写 CSV）
};

class PerfTimer {
public:
    // 开始计时 → 返回 token
    static uint64_t start() {
        return steady_clock::now().time_since_epoch().count();
    }

    // 结束计时 → 记录耗时
    static double stop(const std::string& name, uint64_t start_ns) {
        uint64_t now = steady_clock::now().time_since_epoch().count();
        double ms = (now - start_ns) / 1'000'000.0;
        record(name, ms);
        return ms;
    }

    // 无侵入宏：在整个作用域内自动计时（利用 RAII）
    struct Scoped {
        std::string name;
        uint64_t t0;
        Scoped(const std::string& n) : name(n), t0(PerfTimer::start()) {}
        ~Scoped() { PerfTimer::stop(name, t0); }
    };

    // 打印统计报告
    static void report(const std::string& title = "PERF REPORT") {
        std::lock_guard<std::mutex> lk(mutex_);
        printf("\n");
        printf("╔══════════════════════════════════════════════════════════════════╗\n");
        printf("║  %-60s  ║\n", title.c_str());
        printf("╠══════════════════════╤═══════╤════════╤════════╤════════╤════════╣\n");
        printf("║ Stage                │ count │  avg   │  min   │  max   │ total  ║\n");
        printf("╟──────────────────────┼───────┼────────┼────────┼────────┼────────╢\n");

        double grand_total = 0;
        for (const auto& [name, rec] : records_) {
            double avg = rec.total_ms / rec.count;
            printf("║ %-20s │ %5d │ %6.2f │ %6.2f │ %6.2f │ %6.0f ║\n",
                   name.c_str(), rec.count, avg, rec.min_ms, rec.max_ms, rec.total_ms);
            grand_total += rec.total_ms;
        }
        printf("╟──────────────────────┴───────┴────────┴────────┴────────┼────────╢\n");
        printf("║ TOTAL (serial sum)                                       │ %6.0f ║\n", grand_total);
        printf("╚══════════════════════════════════════════════════════════╧════════╝\n");
    }

    // 写 CSV
    static void write_csv(const std::string& path) {
        std::ofstream f(path);
        f << "stage,count,avg_ms,min_ms,max_ms,total_ms,p50_ms,p99_ms\n";
        for (auto& [name, r] : records_) {
            std::sort(r.samples.begin(), r.samples.end());
            double p50 = percentile(r.samples, 0.50);
            double p99 = percentile(r.samples, 0.99);
            f << name << "," << r.count << "," << (r.total_ms/r.count)
              << "," << r.min_ms << "," << r.max_ms << "," << r.total_ms
              << "," << p50 << "," << p99 << "\n";
        }
        f.close();
        std::cout << "[Perf] CSV written to " << path << std::endl;
    }

    // 重置
    static void reset() {
        std::lock_guard<std::mutex> lk(mutex_);
        records_.clear();
    }

private:
    static void record(const std::string& name, double ms) {
        std::lock_guard<std::mutex> lk(mutex_);
        auto& r = records_[name];
        r.name = name;
        r.total_ms += ms;
        r.count++;
        if (r.count == 1) { r.min_ms = r.max_ms = ms; }
        else { r.min_ms = std::min(r.min_ms, ms); r.max_ms = std::max(r.max_ms, ms); }
        r.samples.push_back(ms);
    }

    static double percentile(std::vector<double>& sorted, double p) {
        if (sorted.empty()) return 0;
        return sorted[std::min((size_t)(sorted.size() * p), sorted.size() - 1)];
    }

    static inline std::map<std::string, PerfRecord> records_;
    static inline std::mutex mutex_;
};

// 便捷宏：PERF_SCOPE(name) 放在函数/代码块开头即可自动计时
#define PERF_SCOPE(name) PerfTimer::Scoped _perf_##__LINE__(name)
```

## 四、专项测试：RGA vs OpenCV

### 4.1 测试目标

对比以下操作的 RGA 硬件加速 vs OpenCV CPU 实现：

| 操作 | RGA | OpenCV | 测试分辨率 |
|------|-----|--------|-----------|
| NV12→RGB | `imcvtcolor` (硬件) | `cv::cvtColor` (CPU) | 1920×1080 |
| NV12→RGB + 缩放至 640×640 | `improcess` (硬件) | `cv::cvtColor` + `cv::resize` | 1920×1080→640×640 |
| RGB→NV12 | `imcvtcolor` (硬件) | `cv::cvtColor` (CPU) | 1920×1080 |
| NV12 拷贝 | `imcopy` (硬件 DMA) | `memcpy` (CPU) | 1920×1080 NV12 |
| BGRA→NV12 叠加 | `imblend` (硬件) | 像素级 Alpha 混合 (CPU) | 1920×1080 |

### 4.2 测试代码

```cpp
// bench/rga_vs_opencv.cpp
#include "bench/perf_timer.h"
#include "RgaUtils.h"
#include "im2d.h"
#include "rga.h"
#include <opencv2/opencv.hpp>
#include <sys/mman.h>
#include <cstring>

void benchmark_rga_vs_opencv(int dmabuf_fd, int w, int h, int iterations) {
    size_t rgb_size = (size_t)w * h * 3;
    size_t nv12_size = (size_t)w * h * 3 / 2;

    for (int i = 0; i < iterations; i++) {
        // ===== 测试 1: RGA NV12→RGB (1920×1080) =====
        {
            uint8_t* bgr_buf = new uint8_t[rgb_size];
            auto t0 = PerfTimer::start();
            NV12_to_BGR_rga(dmabuf_fd, w, h, bgr_buf);
            PerfTimer::stop("RGA_NV12_to_BGR", t0);
            delete[] bgr_buf;
        }

        // ===== 测试 2: OpenCV NV12→RGB (1920×1080) =====
        {
            void* nv12_ptr = mmap(nullptr, nv12_size, PROT_READ, MAP_SHARED, dmabuf_fd, 0);
            cv::Mat nv12_mat(h * 3 / 2, w, CV_8UC1, nv12_ptr);

            auto t0 = PerfTimer::start();
            cv::Mat bgr_mat;
            cv::cvtColor(nv12_mat, bgr_mat, cv::COLOR_YUV2BGR_NV12);
            PerfTimer::stop("OCV_NV12_to_BGR", t0);

            munmap(nv12_ptr, nv12_size);
        }

        // ===== 测试 3: RGA NV12→RGB + 缩放到 640×640 =====
        {
            size_t small_size = 640 * 640 * 3;
            uint8_t* small_bgr = new uint8_t[small_size];
            rga_buffer_handle_t src_h = importbuffer_fd(dmabuf_fd, w, h, RK_FORMAT_YCbCr_420_SP);
            rga_buffer_handle_t dst_h = importbuffer_virtualaddr(small_bgr, small_size);

            auto t0 = PerfTimer::start();
            rga_buffer_t src = wrapbuffer_handle(src_h, w, h, RK_FORMAT_YCbCr_420_SP);
            rga_buffer_t dst = wrapbuffer_handle(dst_h, 640, 640, RK_FORMAT_RGB_888);
            im_rect srect = {0, 0, w, h};
            im_rect drect = {0, 0, 640, 640};
            im_rect prect = {0, 0, 0, 0};
            rga_buffer_t empty;
            memset(&empty, 0, sizeof(empty));
            improcess(src, dst, empty, srect, drect, prect, IM_SYNC);
            PerfTimer::stop("RGA_NV12_to_RGB640", t0);

            releasebuffer_handle(src_h);
            releasebuffer_handle(dst_h);
            delete[] small_bgr;
        }

        // ===== 测试 4: OpenCV NV12→RGB + 缩放到 640×640 =====
        {
            void* nv12_ptr = mmap(nullptr, nv12_size, PROT_READ, MAP_SHARED, dmabuf_fd, 0);
            cv::Mat nv12_mat(h * 3 / 2, w, CV_8UC1, nv12_ptr);

            auto t0 = PerfTimer::start();
            cv::Mat bgr_mat, small_mat;
            cv::cvtColor(nv12_mat, bgr_mat, cv::COLOR_YUV2BGR_NV12);
            cv::resize(bgr_mat, small_mat, cv::Size(640, 640));
            PerfTimer::stop("OCV_NV12_to_RGB640", t0);

            munmap(nv12_ptr, nv12_size);
        }
    }

    PerfTimer::report("RGA vs OpenCV Benchmark");
}
```

### 4.3 预期结果（参考值）

RK3588 上 1920×1080 图像的典型数据（仅供参考）：

| 操作 | RGA | OpenCV | 加速比 |
|------|-----|--------|--------|
| NV12→BGR 色彩转换 | ~1.5ms | ~12ms | **~8x** |
| NV12→RGB + 缩放到 640 | ~2ms | ~15ms | **~7.5x** |
| BGR→NV12 色彩转换 | ~1.5ms | ~10ms | **~6.7x** |
| NV12 帧拷贝 (3MB) | ~0.3ms | ~3ms | **~10x** |
| BGRA→NV12 Alpha 叠加 | ~1ms | ~18ms | **~18x** |

> **关键结论**：RGA 在 1920×1080 分辨率下比 OpenCV 快 6-18 倍。60fps 流水线中，RGA 总共占用约 3-5ms，OpenCV 占用约 40-55ms。**不用 RGA 根本跑不到 60fps。**

## 五、专项测试：NPU 吞吐量

### 5.1 测试矩阵

| 变量 | 取值 | 目的 |
|------|------|------|
| NPU 核心数 | 1核 / 2核 / 3核 | 多核扩展性 |
| 线程池大小 | 1 / 2 / 3 / 4 | 最佳并发度 |
| 输入分辨率 | 640×640 / 416×416 / 320×320 | 精度 vs 速度 |
| 模型 | yolov5s / yolov5n / best.rknn | 模型规模影响 |

### 5.2 测试代码

```cpp
// bench/npu_benchmark.cpp
#include "bench/perf_timer.h"
#include "yolo/yolov5s.h"
#include "pool/thread_poll.h"

void bench_npu_single_thread(const char* model_path, int iterations) {
    Yolov5s yolo(model_path, 0, 1920, 1080);

    // Warmup: 前 3 次不计时（NPU 首次推理有初始化开销）
    detect_result_group_t dummy;
    for (int w = 0; w < 3; w++)
        yolo.inference_image(sample_dmabuf_fd, dummy);

    // 实际测量
    for (int i = 0; i < iterations; i++) {
        detect_result_group_t result;
        yolo.inference_image(sample_dmabuf_fd, result);
        // 计时在 inference_image 内部完成（已插桩）
    }
}

void bench_npu_multi_core(const char* model_path, int num_cores, int iterations) {
    // 分别测试 Core0 alone, Core0+Core1, Core0+1+2
    // 需要修改 yolov5s.cpp 中的 core_mask 设置
    ThreadPoll pool(model_path, num_cores, 1920, 1080);

    for (int w = 0; w < 3; w++) {
        auto fut = pool.submit_task_async(0, sample_dmabuf_fd);
        fut.wait();
    }

    for (int i = 0; i < iterations; i++) {
        auto fut = pool.submit_task_async(i, sample_dmabuf_fd);
        fut.wait();  // 阻塞等待，串行测量单任务延迟
    }
}
```

### 5.3 预期结果（参考值）

RK3588 + YOLOv5s INT8 640×640：

| 配置 | 单帧推理延迟 | 吞吐量 (FPS) | 备注 |
|------|-------------|-------------|------|
| 1核 / 1线程 | ~25ms | ~40 | 基线 |
| 2核 / 2线程 | ~25ms | ~80 | 几乎线性扩展 |
| 3核 / 3线程 | ~25ms | ~115 | 接近线性 |
| 3核 / 4线程 | ~30ms | ~100 | 竞争开销 > 收益 |

> **结论**：最佳配置 = 3 线程 + 3 核，单帧延迟 ~25ms，吞吐 ~115 FPS。再增加线程会因为 NPU 竞争反而下降。

### 6.2 预期流水线时间分布

60fps 目标下每帧预算 = 16.67ms。三线程流水线架构，各阶段时间分布预期：

```
┌────────────────────────────┬──────────┬──────────┐
│ 阶段                       │ 预期耗时 │ 占比     │
├────────────────────────────┼──────────┼──────────┤
│ C  RGA 预处理 (NV12→RGB)   │  ~2.0ms  │   8%     │
│ D  NPU 推理 (INT8, 640²)   │ ~25.0ms  │  70% ★   │
│ E  后处理 (decode+NMS)      │  ~1.5ms  │   4%     │
│ F  IoU 追踪               │  ~0.1ms  │  <1%     │
│ G  CPU 画框 (BGRA)         │  ~1.5ms  │   4%     │
│ H  RGA 合成 (copy+blend)   │  ~2.0ms  │   8%     │
│ I  MPP 硬件编码            │  ~3.0ms  │  12%     │
│ J  RTSP 推流               │  ~1.0ms  │   3%     │
├────────────────────────────┼──────────┼──────────┤
│ 总计 (非并行)              │ ~36.1ms  │          │
└────────────────────────────┴──────────┴──────────┘
```

> **瓶颈是 NPU 推理 (占 70%)**。得益于三线程流水线架构（采集/推理/写出），端到端吞吐由最慢阶段决定：
> - **瓶颈在 NPU**：3线程×25ms ≈ 单帧 8.3ms 有效延迟 → 理论 ~120 FPS
> - **实际受 MPP/GOP 限制**：60fps 编码 → 稳定 60fps 输出
> - **如果检测到 NPU 成为瓶颈**，优化方向：换 yolov5n、降低输入分辨率到 416×416

## 十、执行计划

| 步骤 | 内容 | 时间 |
