# YOLO 模型量化计划 (RK3588 / RKNN)

## 一、背景分析

### 当前状态
| 项目 | 详情 |
|------|------|
| 硬件 | RK3588 (3核 NPU, 6 TOPS) |
| 运行时 | rknn-toolkit-lite2 v2.3.0 (仅推理) |
| 当前模型 | `model/best.rknn` (8.1MB, 已量化 INT8) |
| 模型输入 | 640×640 RGB888, NHWC |
| 检测类别 | helmet, no-helmet, no-vest, person, vest (5类) |
| 后处理 | INT8 输出 → 反量化 (zp + scale) → NMS |
| 推理框架 | YOLOv5s (anchor-based, 3 输出头: 80×80, 40×40, 20×20) |

### 为什么需要重新量化
1. `best.rknn` 可能来自旧的 PyTorch 权重，无法复现或迭代
2. 需要量化新训练的模型（如 YOLOv8/v9/v11 或改进后的 v5）
3. 当前量化精度可能未达最优（需混合量化或 QAT 优化）
4. 建立可复现的量化流程，方便模型迭代

## 二、整体流程

```
PyTorch 模型 (.pt)
    │
    ▼
① 导出 ONNX (.onnx)
    │
    ▼
② ONNX 简化 + 算子验证
    │
    ▼
③ RKNN 模型转换 (FP32 → INT8 量化)
    │  ├── 准备校准数据集 (200-500 张典型场景图)
    │  ├── 配置量化参数 (混合量化 / 逐层精度)
    │  └── 精度验证 (与 FP32 输出对比)
    │
    ▼
④ 板端部署验证
    │  ├── 推理精度测试 (mAP)
    │  ├── 推理速度测试 (ms/帧)
    │  └── 端到端流水线联调
    │
    ▼
⑤ 迭代优化 (如精度不达标)
```

## 四、详细步骤

### 阶段一：ONNX 导出

#### 1.1 从 PyTorch 导出 YOLOv5s ONNX

```python
# export_onnx.py
import torch

# 加载训练好的模型
model = torch.load('best.pt', map_location='cpu')['model'].float()
model.eval()

# 导出 ONNX
dummy_input = torch.randn(1, 3, 640, 640)
torch.onnx.export(
    model,
    dummy_input,
    'yolov5s.onnx',
    input_names=['images'],
    output_names=['output0', 'output1', 'output2'],
    opset_version=12,           # RKNN 推荐 opset 12
    dynamic_axes=None,          # 固定尺寸，不要动态轴
    do_constant_folding=True,
)
print("ONNX exported successfully")
```

#### 1.2 ONNX 简化

```bash
# 简化 ONNX 图结构，移除冗余算子
python -m onnxsim yolov5s.onnx yolov5s_sim.onnx --overwrite-input-shape "images:1,3,640,640"
```

#### 1.3 ONNX 推理验证（确保导出正确）


### 阶段二：RKNN 量化转换

#### 2.1 校准数据集准备

**关键点**：校准数据集的质量直接决定量化精度！

```
dataset/
├── images/
│   ├── scene_001.jpg   # 典型工地场景
│   ├── scene_002.jpg
│   └── ...             # 200-500张
└── dataset.txt         # 每行：图片路径
```

**选取原则**：
- 从实际部署场景的视频流中均匀采样（不同光照、角度、距离）
- 包含有目标和无目标的帧
- 覆盖各种类别组合（单人、多人、戴帽/不戴帽等）
- 排除模糊帧、过曝帧

#### 2.2 量化转换脚本

```python
# convert_rknn.py
from rknn.api import RKNN
import os

# ─── 配置参数 ───
ONNX_PATH = 'yolov5s_sim.onnx'
RKNN_PATH = 'yolov5s_int8.rknn'
DATASET_TXT = 'dataset/dataset.txt'

# 输入尺寸
IMG_H, IMG_W = 640, 640

# ─── 创建 RKNN 对象 ───
rknn = RKNN(verbose=True)

# ─── 1. 配置 ───
rknn.config(
    mean_values=[[0, 0, 0]],          # 不做归一化（YOLOv5 内部处理）
    std_values=[[255, 255, 255]],      # 仅除 255
    target_platform='rk3588',
    quantized_dtype='asymmetric_quantized-8',
    optimization_level=3,              # 0~3, 越高优化越激进但风险越大
)

# ─── 2. 加载 ONNX ───
ret = rknn.load_onnx(model=ONNX_PATH)
if ret != 0:
    print(f"load_onnx failed, ret={ret}")
    exit(1)

# ─── 3. 构建量化模型 ───
ret = rknn.build(
    do_quantization=True,              # 开启 INT8 量化
    dataset=DATASET_TXT,
    rknn_batch_size=1,
)
if ret != 0:
    print(f"build failed, ret={ret}")
    exit(1)

# ─── 4. 导出 RKNN 模型 ───
ret = rknn.export_rknn(RKNN_PATH)
if ret != 0:
    print(f"export failed, ret={ret}")
    exit(1)

print(f"[Done] {RKNN_PATH} exported successfully")

# ─── 5. 精度分析（可选，耗时较长） ───
# rknn.accuracy_analysis(
#     inputs=['dataset/images/scene_001.jpg'],
#     target='rk3588',
# )
```

#### 2.3 混合量化（精度不够时使用）

如果 INT8 量化后精度下降超过 2-3%，可对关键层使用混合量化：

```python
# 在 build() 之前插入
# 方案A：自动混合量化
rknn.config(..., quantized_dtype='asymmetric_quantized-8')

# 方案B：手动指定敏感层保持 FP16
# 通常只需要对检测头（输出层）保留较高精度
rknn.hybrid_quantization_step1(dataset=DATASET_TXT)
# 查看生成的 profile 文件，找出量化敏感层
# 然后：
# rknn.hybrid_quantization_step2(
#     model_input='model.onnx',
#     data_input='step1_profile.txt',
#     ...
# )
```

### 阶段三：精度验证 (PC 端模拟)

```python
# verify_accuracy.py
from rknn.api import RKNN
import numpy as np
import cv2

rknn = RKNN()
rknn.load_rknn('yolov5s_int8.rknn')
rknn.init_runtime(target='rk3588')

# 对比 FP32 ONNX 和 INT8 RKNN 的输出余弦相似度
IMG = 'dataset/images/test.jpg'
img = cv2.imread(IMG)
img = cv2.resize(img, (640, 640))
img_rgb = cv2.cvtColor(img, cv2.COLOR_BGR2RGB)
img_input = np.expand_dims(img_rgb, 0)

# RKNN 推理
outputs_int8 = rknn.inference(inputs=[img_input])

# 计算各层与 FP32 的余弦相似度（需有 onnxruntime 参考输出）
# cosine_sim > 0.95 视为可接受
```

**精度标准**：
| 指标 | 可接受 | 良好 |
|------|--------|------|
| 余弦相似度 (每层) | > 0.90 | > 0.95 |
| mAP@0.5 下降 | < 3% | < 1% |
| 推理延迟 | < 50ms | < 35ms |

## 五、常见问题与预案

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 量化后框全消失 | 某些层量化敏感度过高 | 混合量化：检测头保留 FP16 |
| 置信度整体偏低 | 校准集分布与实际场景不匹配 | 从实际视频流重新采样校准集 |
| rknn_build 报错 "unsupported op" | ONNX 中有 RKNN 不支持的算子 | 修改模型结构或 ONNX opset，必要时提 issue |
| 推理时输出 shape 不对 | ONNX 导出时 dynamic shape 未固定 | 重新导出固定尺寸的 ONNX |
| 板端 rknn_run 失败 | RKNN API 版本不匹配 | 确保 PC 端 rknn-toolkit2 和板端 rknn-toolkit-lite2 版本一致 |
| 量化后某类别丢得厉害 | 校准数据集中该类别样本不足 | 针对性补充该类别的校准图 |
| 推理速度 > 50ms | 模型过大或优化等级不够 | 提高 optimization_level, 或换 YOLOv5n/v6n |
