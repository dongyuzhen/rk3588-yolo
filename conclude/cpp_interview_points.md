# 🎯 rk3588-yolo 项目专属 C++ 面试八股速记指南

别死记硬背了！面试官问八股文时，你直接结合自己写的代码来回答，这叫“项目落地”，不仅好记，还能瞬间秒杀 90% 只会背书的候选人。以下是你在这个项目里**真实用到的** C++ 核心考点：

## 1. 多线程与并发 (多线程八股)
这个项目是个典型的多媒体流水线（取流 -> 推理 -> 推流），多线程是**绝对的重头戏**。

*   **考点：线程池 (Thread Pool) 怎么实现？**
    *   **你的代码体现**：`pool/thread_poll.h`
    *   **话术**：“为了避免频繁创建销毁线程的开销，我手写了一个基于 C++11 的线程池。底层用 `std::vector<std::thread>` 管理工作线程，用 `std::queue` 存放任务，通过 `std::mutex` 保证队列的线程安全，用 `std::condition_variable` 来阻塞/唤醒空闲线程处理任务。”
*   **考点：`std::mutex` 与 `std::condition_variable` 的配合**
    *   **你的代码体现**：`SafeQueue.h` / `pool/thread_poll.cpp`
    *   **话术**：“条件变量必须和 `std::unique_lock<std::mutex>` 配合使用。当任务队列为空时，工作线程调用 `cv.wait(lock)` 挂起并自动释放锁；当有新任务入队时，主线程调用 `cv.notify_one()` 唤醒工作线程，工作线程被唤醒后会自动重新获取锁去取任务。”
*   **考点：为什么用 `std::unique_lock` 而不是 `std::lock_guard`？**
    *   **话术**：“`lock_guard` 是轻量级的 RAII 锁，只能在作用域内全程加锁。而条件变量 `wait` 的时候需要临时解锁，等唤醒时再加锁，这就必须用更灵活的 `unique_lock`。”
*   **考点：生产者-消费者模型**
    *   **你的代码体现**：摄像头取帧（生产者） -> `SafeQueue` -> YOLO 推理（消费者）。
    *   **话术**：“项目中我大量使用了生产者-消费者模型解耦。比如 V4L2 摄像头抓取图像存入线程安全的队列（基于互斥锁保护的 SafeQueue），另一个推理线程不断从队列取图送给 NPU 推理。这样两者速率不匹配时也不会互相阻塞。”

## 2. 现代 C++ 特性 (C++11/14 八股)

*   **考点：右值引用与 `std::move`**
    *   **你的代码体现**：线程池任务入队、大块图像数据传递。
    *   **话术**：“在传递大对象（比如存有高分辨率图像数据的 vector 或复杂结构体）时，我会用 `std::move` 将左值转化为右值，触发移动语义，避免深拷贝，极大地降低了内存拷贝的开销，尤其是在 RK3588 这种边缘计算板子上，内存带宽非常宝贵。”
*   **考点：`auto` 关键字与 Lambda 表达式**
    *   **你的代码体现**：线程池的 `commit` 提交任务。
    *   **话术**：“在给线程池提交任务时，我大量使用了 Lambda 表达式封装闭包任务。对于长长的类型（比如复杂的迭代器或泛型返回类型），使用 `auto` 可以让代码更清爽。但在关键的接口处我还是会明确指定类型，保证可读性。”

## 3. 内存管理与底层控制 (内存八股)

*   **考点：智能指针 `std::shared_ptr` / `std::unique_ptr`**
    *   **你的代码体现**：项目中的资源管理机制。
    *   **话术**：“对于独占的资源，我会优先使用 `std::unique_ptr` 保证零开销的 RAII。如果某个图像帧需要在多条流水线（比如一边给推流模块，一边给 NPU 推理）共享，我会用 `std::shared_ptr`，通过引用计数自动管理生命周期，避免悬挂指针。”
*   **考点：内存泄漏排查 (Valgrind)**
    *   **你的代码体现**：项目的系统级 Debug。
    *   **话术**：“我在项目中用 Valgrind (Memcheck) 彻底排查过内存问题。因为有 OpenCV 和 FFmpeg，我不仅掌握了怎么查普通的 Definitely lost，还学会了通过 `--track-origins=yes` 抓出未初始化变量导致的条件跳转 Bug。”
*   **考点：零拷贝与物理连续内存 (🌟 高级加分项，必说)**
    *   **你的代码体现**：`camera/cma_buffer.cpp`，RKNN, RGA 的配合。
    *   **话术（绝杀）**：“普通的 C++ 八股只问堆栈和 `new/delete`，但在我的项目中，为了发挥 RK3588 芯片的极限性能，我绕开了普通的虚拟内存。我通过 DMA/CMA 申请**物理连续内存**，让 V4L2 抓到的数据直接以**零拷贝 (Zero-copy)** 的方式送给 2D 硬件加速器 (RGA) 做格式转换和缩放，最后直通 NPU (RKNN)。全程不需要 CPU 参与数据搬运，极大降低了 CPU 负载！”

## 4. 面向对象与设计模式 (OOP 八股)

*   **考点：多态机制 (`virtual` 与 `override`)**
    *   **你的代码体现**：抽象接口的设计。
    *   **话术**：“项目中定义了基类和虚函数接口，底层通过虚函数表 (vptr 和 vtbl) 实现动态绑定。我在派生类重写时一定会加上 `override` 关键字，让编译器帮我检查函数签名是否匹配，避免因为参数写错导致隐式地重载了函数而不是覆盖。”
*   **考点：单例模式 (Singleton) 的线程安全**
    *   **话术**：“如果需要全局管理器，我使用的是 C++11 的 **Meyers 单例**（利用局部静态变量）。不仅代码极短，而且 C++11 标准在底层保证了局部静态变量初始化的**线程安全**，再也不用手写繁琐的双重检查锁定 (DCL) 和互斥锁了。”
