# 项目总结

## 项目目标

在 RK3588（Rock 5C）嵌入式平台上，实现一条**端到端实时目标检测推流流水线**：

> USB 摄像头 → NPU 目标检测 → 画框 → H.264 硬编码 → RTMP 推流

核心挑战：在 CPU/内存资源受限的嵌入式环境中，通过零拷贝机制让各硬件单元（ISP→RGA→NPU→VPU）之间直接共享内存，避免 CPU 搬运数据的瓶颈。

---

## 最终实现的技术链路

```
摄像头（V4L2 DMABUF/CMA）
  → RGA（YUYV→RGB，色彩转换）
  → RGA（RGB 640×480→640×640，缩放）
  → RKNN NPU（YOLOv5s 推理）
  → 后处理（NMS，坐标还原）
  → RGA（YUYV→BGR，画框准备）
  → OpenCV（画框，CPU）
  → RGA（BGR→NV12，编码准备）
  → MPP VPU（H.264 硬编码）
  → FFmpeg（RTMP 推流 + AVI 本地录制）
```

三段流水线由三个线程并行执行，中间用线程安全队列 + `std::future` 异步传递结果。

---

## 核心技术点与解决方案

### 1. V4L2 DMABUF 零拷贝采集

- 使用 `V4L2_MEMORY_DMABUF` 内存模式，摄像头驱动直接 DMA 写入 CMA 物理连续内存
- 用户态通过 `dmabuf fd` 引用这块内存，而不是 mmap 后 memcpy
- `CmaBuffer` 封装了 `/dev/dma_heap/cma` 的分配、mmap、cache sync 操作

### 2. RGA 两步转换（解决 YUYV 限制）

RGA3（RK3588）不支持以 YUYV 为 src 同时做缩放（`imresize`）。解决方案是拆成两步：
- **步骤 A**：`imcvtcolor(YUYV→RGB888)`，尺寸不变（640×480）
- **步骤 B**：`imresize(RGB888→RGB888)`，仅缩放（640×480→640×640）

中间缓冲用 `rknn_create_mem` 分配，避免额外占用 CMA，其 fd 可直接被 RGA 通过 IOMMU 访问。

### 3. RGA Linux API 正确用法

Linux 下 `wrapbuffer_fd` 宏是 Android Only，正确方式是：
```
importbuffer_fd(fd, w, h, format) → rga_buffer_handle_t
wrapbuffer_handle(handle, ...)    → rga_buffer_t
操作完毕 → releasebuffer_handle(handle)
```

### 4. RKNN 零拷贝推理

- `rknn_create_mem` 创建带 fd 的内存，可直接被 RGA 写入
- `rknn_set_io_mem` 将该内存绑定为模型输入，NPU 直接从 RGA 的输出内存读取数据
- 两步 RGA + `rknn_set_io_mem` 实现了"摄像头→RGA→NPU"全链路零拷贝

### 5. MPP 零拷贝编码

- NV12 缓冲来自 `/dev/dma_heap/system`（非 CMA，节省 CMA 内存）
- 使用 `mpp_buffer_group_get_external(MPP_BUFFER_TYPE_EXT_DMA)` 创建外部 buffer group
- `mpp_buffer_import_with_tag` 把 NV12 fd 导入，MPP 编码器通过 IOMMU 直接访问，无 memcpy

**关键坑**：import 必须用 `MPP_BUFFER_TYPE_EXT_DMA` 类型的 external group，不能用内部 `DMA_HEAP` group（会报 `MPP_ERR_NOMEM`）。

### 6. CMA 内存紧张问题

RK3588 CmaTotal 只有 8MB，多处需要 CMA 的组件同时运行时容易 OOM：
- V4L2 采集缓冲（CMA）× 4 ≈ 2.4MB
- RKNN 内部内存 ≈ 3-4MB

解决方案：
- NV12 工作缓冲改用 `/dev/dma_heap/system`（不占 CMA）
- RKNN mid_mem 通过 `rknn_create_mem` 分配（MPP 内部堆，不走 CMA）
- V4L2 缓冲数从 6 减到 4，线程数从 3 减到 2

## 遇到并解决的主要 Bug

| 问题 | 根因 | 解决方案 |
|------|------|----------|
| `VIDIOC_S_FMT: Invalid argument` | 使用了 `/dev/video1`（metadata 节点）而非 `/dev/video0` | 改为 `/dev/video0`，分辨率改为 640×480 |
| `RGA Unsupported function: Invalid src format [0x280]` | YUYV 不能作为 `imresize` 的 src | 拆成两步：先 `imcvtcolor` 再 `imresize` |
| `RGA Invalid parameters: wstride < width` | `wrapbuffer_fd` 宏参数顺序错误（把 width 传给了 format 位置） | 改为4参数形式：`wrapbuffer_fd(fd, w, h, format)` |
| `RGA Fatal error: Failed to call RockChipRga` | 中间缓冲用普通 `std::vector` 堆内存，物理不连续 | 改用 `rknn_create_mem` 分配（DMA 物理连续内存） |
| `RGA importbuffer_fd failed: h_mid=0` | `CmaBuffer` 分配失败（CMA 内存不足），fd=-1 | 改用 `rknn_create_mem` 代替手动 CMA 分配 |
| `mpp_buffer_import_with_tag failed, ret=-2` | 用了 `MPP_BUFFER_TYPE_DMA_HEAP` 的 internal group 接收外部 fd | 改用 `MPP_BUFFER_TYPE_EXT_DMA` external group |
| `DMA_HEAP_IOCTL_ALLOC: Cannot allocate memory` | NV12 缓冲也用 CMA 分配，CMA 耗尽 | NV12 缓冲改用 `/dev/dma_heap/system` |

## 可扩展方向

1. **MIPI 摄像头支持**：将格式从 `YUYV_422` 改为 `YCbCr_420_SP`（NV12），摄像头节点改为 ISP 输出节点（如 `/dev/video11`），写线程可跳过 BGR→NV12 转换，直接把摄像头帧送 MPP
2. **多路推流**：扩展 `StreamerContext` 为数组，每路独立 RTMP 地址
3. **模型替换**：换用其他 `.rknn` 模型（YOLOv8、PPYOLOE 等），需更新 `post_process.cpp` 的输出解析逻辑
4. **动态分辨率**：将 `640×480` 改为运行时参数，对应修改 `g_width/g_height` 及 `yolo.img_width/img_height`
5. **CMA 扩容**：修改内核启动参数 `cma=32M` 可解除 CMA 内存瓶颈，解锁更多并发线程
