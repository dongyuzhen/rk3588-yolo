# 测试方法

本文档覆盖当前零拷贝推理流水线的完整测试体系，从环境准备到各模块单测、集成测试、性能测试，逐步展开。

---

## 1. 环境准备

### 1.1 确认设备与驱动

```bash
# 确认摄像头节点存在
ls /dev/video*
# 预期：/dev/video0（USB UVC 或 MIPI ISP 主输出节点）

# 查询 video0 支持的格式和分辨率
v4l2-ctl --device=/dev/video0 --list-formats-ext
# 确认 YUYV 640x480 @ 30fps 在列表中

# 确认 NPU 驱动加载
ls /dev/rknpu* /dev/mpp_service
# 预期：/dev/rknpu0 /dev/mpp_service

# 确认 RGA 驱动
ls /dev/rga*
# 预期：/dev/rga（或 /dev/rga3e）

# 确认 CMA 和 system 堆节点
ls /dev/dma_heap/
# 预期：cma  system

# 查看 CMA 可用内存（本项目 CMA 较紧张，重要！）
grep -E "CmaTotal|CmaFree" /proc/meminfo
```

### 1.2 编译项目

```bash
cd /home/radxa/project
mkdir -p build && cd build
cmake .. && cmake --build . --target app -j4
# 预期最后一行：[100%] Built target app
```

### 1.3 目录结构确认

```
project/
├── build/app          # 可执行文件
├── model/
│   ├── yolov5s.rknn       # NPU 模型（必须存在）
│   └── coco_80_labels_list.txt
└── output.avi         # 运行后生成（在 build/ 的上一级）
```

## 2. 单模块测试

### 2.1 摄像头采集测试

验证 V4L2 DMABUF 采集是否正常，不涉及推理和编码。

```bash
# 方法1：用 v4l2-ctl 直接抓一帧原始数据
v4l2-ctl --device=/dev/video0 \
  --set-fmt-video=width=640,height=480,pixelformat=YUYV \
  --stream-mmap --stream-count=1 \
  --stream-to=/tmp/frame.yuyv

# 查看文件大小，YUYV 640x480 = 614400 字节
ls -la /tmp/frame.yuyv
# 预期：614400

# 方法2：用 ffmpeg 查看摄像头画面（需要 X11 或 VNC）
ffmpeg -f v4l2 -input_format yuyv422 -video_size 640x480 \
  -i /dev/video0 -vframes 1 /tmp/test_frame.jpg
# 查看 /tmp/test_frame.jpg 确认图像正常
```

### 2.2 RGA 转换测试

单独验证 RGA 的格式转换和缩放是否正常。

```bash
# 用 rgaImDemo 工具测试（Rockchip 官方测试工具）
# 查看 RGA 版本
rgaImDemo --querystring=version

# 测试色彩转换（YUYV→RGB 方向，通过 copy 验证 RGA 基础可用性）
rgaImDemo --copy

# 测试缩放功能
rgaImDemo --resize=down    # 缩小
rgaImDemo --resize=up      # 放大

# 测试格式转换
rgaImDemo --cvtcolor

# 循环运行 10 次，检查稳定性
rgaImDemo -w10 --copy
```

**验证点**：输出日志中看到 `copying .... Run successfully`，无 `Fatal error`。

### 2.3 RKNN 推理测试

单独验证 NPU 推理是否正常（不通过完整流水线）。

```bash
# 检查 RKNN 库版本
strings /home/radxa/project/3rdparty/librknn_api/aarch64/librknnrt.so | grep "librknn"

# 确认 NPU 状态
cat /sys/kernel/debug/rknpu/load 2>/dev/null || echo "需要 root 权限"

# 运行项目（无 RTMP 模式），观察 RKNN 初始化日志
cd /home/radxa/project/build
./app --no-rtmp 2>&1 | head -50
# 预期看到：
# Yolov5s[0] init OK
# n_input=1 n_output=3
# model input: 640x640x3
# labels.size()=80   ← 后处理初始化成功
```

### 2.4 MPP 编码测试

单独验证 MPP H.264 编码（不涉及 RTMP）。

```bash
# 用 mpi_enc_test 工具（Rockchip 官方编码测试）
# 生成一个 NV12 测试输入文件（640x480）
ffmpeg -f lavfi -i color=red:size=640x480:rate=30 \
  -frames:v 30 -pix_fmt nv12 /tmp/test_nv12.raw

# 调用 mpi_enc_test 编码
mpi_enc_test -i /tmp/test_nv12.raw -o /tmp/test_out.h264 \
  -w 640 -h 480 -f 4 -t 7 -n 30
# -f 4 = NV12, -t 7 = H.264
# 预期：encoded 30 frames

# 验证输出
ffprobe /tmp/test_out.h264
```

### 2.5 RTMP 服务器测试（推流前置检查）

```bash
# 确认能 ping 通 RTMP 服务器
ping -c 3 192.168.137.1

# 确认 RTMP 端口开放（需要服务器端运行 nginx-rtmp 或 OBS）
nc -zv 192.168.137.1 1935
# 预期：Connection succeeded

# 服务器端启动（Windows/PC 端）：OBS → 工具 → 服务器 → rtmp://0.0.0.0:1935/live
# 或 nginx.conf 配置 rtmp { server { listen 1935; application live { live on; } } }
```

## 3. 集成测试

### 3.1 基础运行测试（无 RTMP）

最小风险的完整流水线测试，不需要 PC 端 RTMP 服务器。

```bash
cd /home/radxa/project/build
./app --no-rtmp
```

**观察要点**：
| 日志关键字 | 含义 | 预期 |
|---|---|---|
| `Yolov5s[N] init OK` | NPU 模型加载 | 出现 N 次（= 线程数） |
| `model input: 640x640x3` | 模型输入尺寸 | 必须出现 |
| `labels.size()=80` | 后处理标签加载 | 必须为 80 |
| `get mpp buffer group` | MPP 初始化 | 必须出现 |
| `mpp: mpp_init ok` | MPP 编码器就绪 | 必须出现 |
| `[mpp] fd encode frame 0` | 第一帧编码成功 | 运行约 1s 后出现 |
| `[Process] yolo failed` | 推理失败 | 不应出现 |
| `[mpp] mpp_buffer_import_with_tag failed` | MPP 导入失败 | 不应出现 |

运行 500 帧后自动退出，检查输出视频：
```bash
# 查看生成的视频文件
ls -lh /home/radxa/project/output.avi

# 用 ffprobe 检查视频信息
ffprobe /home/radxa/project/output.avi
# 预期：Video: h264, yuv420p, 640x480, 30fps

# 播放验证（需要 X11）
ffplay /home/radxa/project/output.avi
```

### 3.2 RTMP 推流测试

```bash
cd /home/radxa/project/build
./app   # 不加 --no-rtmp，默认开启推流
```

**PC 端用 VLC 拉流验证**：
```
媒体 → 打开网络串流 → rtmp://192.168.137.1:1935/live/app
```
或 ffplay：
```bash
ffplay rtmp://192.168.137.1:1935/live/app
```

**验证点**：
- 画面正常显示，无绿屏、花屏
- 检测框出现在正确位置
- 延迟 < 500ms

### 3.3 压力/稳定性测试

修改 `DEFAULT_FRAME_LIMIT` 后重新编译，或直接修改运行方式：

```bash
# 修改 main.cpp 第52行，改为更大的帧数
# constexpr int DEFAULT_FRAME_LIMIT = 3000;  // ~100秒
# 重新编译后运行

# 同时监控资源占用
watch -n 1 'grep -E "CmaFree|MemFree" /proc/meminfo'

# 另一个终端监控 CPU/NPU
top -b -n 60 -d 2 | grep -E "app|CPU"

# 检查是否有内存泄漏（运行前后对比）
grep CmaFree /proc/meminfo
./app --no-rtmp
grep CmaFree /proc/meminfo
# 两次 CmaFree 应该相近（差值 < 1MB）
```

## 4. 性能测试

### 4.1 帧率统计

在 `main.cpp` 的 `writeThreadFunc` 里查看编码帧计数：
```bash
# 观察编码帧率日志（每 30 帧打印一次）
./app --no-rtmp 2>&1 | grep "fd encode frame"
# 观察帧号递增速度，用时间戳计算实际帧率
```

更精确的方法：
```bash
# 对输出视频统计实际帧率
ffprobe -v error -select_streams v:0 \
  -count_packets -show_entries stream=nb_read_packets \
  -of csv=p=0 /home/radxa/project/output.avi
# 除以录制时间即帧率
```

### 4.2 NPU 利用率

```bash
# RK3588 NPU 利用率（需要 root）
cat /sys/kernel/debug/rknpu/load

# 或使用 rknn_server 工具
rknn_server &
# 然后在另一端查看
```

### 4.3 端到端延迟测试

```bash
# 用 ffmpeg 推流，同时用 ffplay 拉流，目测画面与现实的延迟
# 在摄像头前拍手表秒针，对比 VLC/ffplay 显示的时间差
ffplay -fflags nobuffer -flags low_delay \
  rtmp://192.168.137.1:1935/live/app
```

### 4.4 RGA 转换时间测量

在 `yolov5s.cpp` 的 RGA 步骤前后加时间戳（调试用）：
```cpp
auto t0 = std::chrono::steady_clock::now();
// imcvtcolor ...
auto t1 = std::chrono::steady_clock::now();
printf("RGA step A: %ld us\n",
  std::chrono::duration_cast<std::chrono::microseconds>(t1-t0).count());
```

## 5. 常见问题排查

### 5.1 摄像头打不开
```bash
# 确认节点权限
ls -la /dev/video0
# 若需要加 video 组
sudo usermod -aG video $USER

# 确认没有其他进程占用
fuser /dev/video0
```

### 5.2 RGA 报错
```bash
# 查看详细 RGA 驱动日志
dmesg | grep -i rga | tail -20

# 确认 RGA 设备权限
ls -la /dev/rga*
```

### 5.3 CMA 内存不足
```bash
grep -E "CmaTotal|CmaFree" /proc/meminfo
# CmaFree 低于 3MB 时容易失败
# 减少 BUFFER_NUM（main.cpp:47）或 PROCESS_THREAD_NUM（main.cpp:54）
```

### 5.4 RTMP 连接失败
```bash
# 检查网络
ping 192.168.137.1
# 检查 RTMP 端口
telnet 192.168.137.1 1935
# 确认 RTMP server 正在运行（PC 端开 OBS/nginx-rtmp）
```

### 5.5 推理全部失败（yolo failed）
```bash
# 确认模型文件存在
ls -lh /home/radxa/project/model/yolov5s.rknn

# 确认 NPU 驱动
ls /dev/rknpu*

# 查看详细错误
./app --no-rtmp 2>&1 | grep -E "yolo|rknn|RGA"
```
DMA-BUF 同步原则
Copy code to clipboard
CPU 写 → DMA 读：需要 flush（写回物理内存）
DMA 写 → CPU 读：需要 invalidate（清除 CPU stale cache）
DMA → DMA：不涉及 CPU cache，无需同步
